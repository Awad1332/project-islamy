# تطبيق WFCostore لنظام Android (WebView)

تطبيق Android أصلي بلغة Kotlin يعرض المتجر الحقيقي **https://wfcostore.com/ar** داخل WebView مضبوط أمنيًا. لا يعيد التطبيق بناء المتجر ولا يحتوي على بيانات تجريبية: كل الصفحات والسلة والحساب والدفع تأتي من الموقع نفسه.

> **تنبيه مهم عن حالة التحقق:** بيئة البناء التي أُنشئ فيها المشروع لم تكن تسمح بالوصول إلى `wfcostore.com` ولا إلى `dl.google.com` (مستودع Google Maven وأدوات Android SDK). لذلك:
> - لم يُفحص الموقع، فاسم المتجر وألوانه ونطاقات الدفع وتسجيل الدخول **غير متحقق منها** (التفاصيل في قسم «ما يجب التحقق منه»).
> - لم يُنفَّذ `assembleDebug` فعليًا. نُفِّذت فقط اختبارات الوحدة لمنطق التنقل (14/14 ناجحة) على JVM.
> - أول خطوة عندك: افتح المشروع في Android Studio ونفّذ البناء (خطوة واحدة، انظر أدناه).

└── keystore.properties.example   ← قالب إعدادات التوقيع (لا أسرار في المستودع)

## 3. فتح المشروع في Android Studio

1. ثبّت أحدث إصدار من Android Studio (Ladybug أو أحدث).
2. **File → Open** واختر مجلد `wfcostore-android` (وليس جذر المستودع).
3. اقبل تنزيل Gradle وأي SDK Platform 35 يطلبه Android Studio.
4. انتظر انتهاء **Gradle Sync**، ثم اختر جهازًا أو محاكيًا واضغط **Run ▶**.

سطر الأوامر (يتطلب Android SDK وملف `local.properties` يحتوي `sdk.dir=...`، يُنشئه Android Studio تلقائيًا):

```bash
cd wfcostore-android
./gradlew testDebugUnitTest      # اختبارات الوحدة
./gradlew assembleDebug          # APK للتجربة
```

## 4. بناء نسخة Debug APK

```bash
./gradlew assembleDebug
# الناتج: app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```
أو من Android Studio: **Build → Build App Bundle(s) / APK(s) → Build APK(s)**.

## 5. التوقيع ونسخة Release

### إنشاء مفتاح الرفع (مرة واحدة)
```bash
keytool -genkeypair -v -keystore keys/wfcostore-upload.jks -alias upload \
        -keyalg RSA -keysize 2048 -validity 10000
```
احتفظ بالملف وكلمات المرور في مكان آمن خارج المستودع (مدير كلمات مرور + نسخة احتياطية). ملفات `*.jks` و`keystore.properties` مستثناة في `.gitignore`.

### ربط المفتاح بالبناء
انسخ `keystore.properties.example` إلى `keystore.properties` واملأ القيم، أو عرّف متغيرات البيئة (مناسبة لـ CI):
`WFC_KEYSTORE_FILE`، `WFC_KEYSTORE_PASSWORD`، `WFC_KEY_ALIAS`، `WFC_KEY_PASSWORD`.

### البناء
```bash
./gradlew assembleRelease   # APK موقّع: app/build/outputs/apk/release/app-release.apk
./gradlew bundleRelease     # AAB لـ Google Play: app/build/outputs/bundle/release/app-release.aab
```
إذا لم يوجد مفتاح يُبنى الإصدار غير موقّع (`app-release-unsigned.apk`)، ولا يمكن تثبيته أو رفعه قبل توقيعه.
نسخة Release تستخدم R8 لتصغير الكود والموارد.

**Play App Signing:** عند أول رفع على Google Play فعّل «Play App Signing»؛ المفتاح أعلاه يصبح «مفتاح الرفع» وتحتفظ Google بمفتاح التوقيع النهائي.

## 7. ما تم تنفيذه

**WebView**
- تحميل `https://wfcostore.com/ar` عند الفتح، مع مؤشر تقدّم أعلى الشاشة.
- JavaScript مفعّل لأن السلة وخيارات المنتجات والدفع تعتمد عليه. DOM Storage والكوكيز مفعّلة، والكوكيز تُحفظ (`flush`) بعد كل صفحة وعند الخروج من التطبيق، فتبقى الجلسة والسلة.
- الكوكيز من طرف ثالث مفعّلة (`ALLOW_THIRD_PARTY_COOKIES`) لأن إطارات 3-D Secure لبوابات الدفع تحتاجها عادة؛ يمكن تعطيلها إن نجح الدفع بدونها.
- RTL والعربية تُعرض كما يقدّمها الموقع، دون تغيير في الصفحات.
- التكبير بالإصبعين مسموح دون أزرار تكبير، ويُحترم `viewport` الخاص بالموقع.
- التدوير وتغيير حجم النافذة لا يعيدان تحميل الصفحة (`configChanges`). عند قتل النظام للتطبيق في الخلفية يُستعاد سجل التصفح (`saveState`).
- انهيار محرّك العرض (Renderer) لا يُسقط التطبيق: يُعاد إنشاء WebView وتحميل آخر صفحة.
- العرض من حافة إلى حافة (Android 15) مع مراعاة شريط الحالة وشريط التنقل والنتوء ولوحة المفاتيح.

**الأخطاء**
- شاشة خطأ بالعربية مع زر «إعادة المحاولة» عند: انقطاع الإنترنت، فشل الاتصال، أخطاء الخادم 5xx، أخطاء شهادة SSL.
- عند عودة الاتصال تُعاد المحاولة تلقائيًا.
- صفحات 4xx (مثل صفحة 404 الخاصة بالمتجر) يعرضها الموقع كما هي.

**قواعد التنقل** (`UrlPolicy.kt`)

| الرابط | السلوك |
|---|---|
| `https://wfcostore.com` و`www.wfcostore.com` | داخل التطبيق |
| `http://` إلى المتجر | يُحوَّل إلى `https://` |
| أي `http://` آخر | لا يُحمَّل داخل التطبيق إطلاقًا |
| واتساب (`wa.me`، `whatsapp.com`، `whatsapp://`)، `tel:`، `mailto:`، `sms:`، الشبكات الاجتماعية، الخرائط | التطبيق المناسب في الجهاز |
| `intent://` | يُفتح بطريقة Chrome الآمنة (أنشطة BROWSABLE فقط، مع رابط بديل https) |
| إعادة توجيه (redirect) من المتجر أو بوابة دفع إلى نطاق آخر | داخل التطبيق: هذا هو مسار الدفع وتسجيل الدخول، ولا يفقد المستخدم جلسته |
| أي رابط داخل صفحة بوابة دفع (مثل صفحة البنك للتحقق 3-D Secure) | داخل التطبيق |
| نطاقات `TRUSTED_FLOW_HOST_SUFFIXES` | داخل التطبيق حتى لو نقر المستخدم رابطًا إليها |
| رابط نقره المستخدم إلى موقع خارجي غير معروف | المتصفح الخارجي |
| `javascript:`، `file:`، `content:`، `data:`، `blob:` في الإطار الرئيسي | محظور |
| فتح تطبيقات خارجية دون نقرة من المستخدم من صفحات المتجر | محظور |
| `target="_blank"` / `window.open` | تُطبَّق عليه القواعد نفسها: صفحات المتجر تُفتح في النافذة نفسها، والباقي خارجيًا. النوافذ المنبثقة دون نقرة تُرفض |

**وظائف أخرى**
- زر الرجوع يرجع داخل WebView، ويغلق التطبيق فقط عندما لا توجد صفحة سابقة.
- السحب للأسفل للتحديث، ولا يعمل إلا عندما تكون الصفحة في أعلاها.
- رفع الملفات والصور عبر منتقي ملفات النظام، دون صلاحية تخزين أو كاميرا.
- التنزيل عبر DownloadManager إلى مجلد Downloads على Android 10+، دون صلاحيات. على Android 7–9 يُفتح الرابط في المتصفح لتجنّب طلب صلاحية تخزين.
- نوافذ JavaScript (`alert`/`confirm`/`prompt`/`beforeunload`) تظهر كحوارات Material بعنوان النطاق الذي أطلقها.
- منع النقرات المكررة على الروابط الخارجية وزر إعادة المحاولة.
- Deep links / App Links لروابط `https://wfcostore.com/...` (انظر القسم 9).

## 8. الأمان والخصوصية

- **لا تجاوز لأخطاء SSL مطلقًا**: `handler.cancel()` دائمًا، مع عرض شاشة خطأ.
- `usesCleartextTraffic=false` و`network_security_config` يمنعان HTTP، ولا يُوثق إلا بشهادات النظام. `MIXED_CONTENT_NEVER_ALLOW`.
- لا توجد أي `JavascriptInterface`: صفحات الويب لا تستطيع استدعاء كود أصلي.
- `allowFileAccess=false` و`allowContentAccess=false`.
- Google Safe Browsing مفعّل، وإرسال مقاييس استخدام WebView إلى Google معطّل.
- طلبات الويب للكاميرا والميكروفون والموقع تُرفض تلقائيًا.
- النسخ الاحتياطي معطّل (`allowBackup=false` وقواعد استبعاد شاملة)، فلا تُنقل كوكيز الدخول إلى جهاز آخر.
- لا تُسجّل الروابط أو البيانات في Logcat في نسخة Release. نسخة Debug تسجّل **اسم النطاق فقط** للروابط المفتوحة خارجيًا، لمساعدتك على ضبط قائمة النطاقات.
- تصحيح WebView عن بعد (`chrome://inspect`) مفعّل في Debug فقط.
- التطبيق لا يجمع بيانات بطاقات ولا يعالج الدفع: كل ذلك يتم في صفحات المتجر وبوابة الدفع.

**الصلاحيات المطلوبة:** `INTERNET` و`ACCESS_NETWORK_STATE` (لاكتشاف انقطاع الاتصال وعودته). لا شيء غيرهما.

**البيانات التي يتعامل معها التطبيق:** كوكيز وبيانات Local Storage التي يضعها الموقع وبوابات الدفع داخل WebView، وتُخزَّن محليًا في الجهاز فقط. التطبيق نفسه لا يرسل بيانات إلى أي خادم غير المتجر والنطاقات التي يفتحها المتجر. الملفات التي يختارها المستخدم للرفع تُرسل إلى الموقع فقط.

> هذا وصف تقني وليس رأيًا قانونيًا. نموذج «أمان البيانات» في Google Play وسياسة الخصوصية يجب أن يغطيا ما يجمعه **الموقع** نفسه (الحساب، العناوين، الطلبات، أدوات التحليلات الموجودة فيه). راجعهما مع صاحب المتجر.

## 9. ما يجب التحقق منه قبل النشر (لم يُختبر بسبب قيود البيئة)

1. **اسم المتجر:** الاسم الحالي `WFCostore` مأخوذ من النطاق. ضع الاسم الرسمي بالعربية والإنجليزية.
2. **الشعار والألوان:** ضع الشعار الرسمي (لم أُنشئ شعارًا للمتجر) وألوانه.
3. **نطاقات الدفع وتسجيل الدخول:** نفّذ عملية شراء تجريبية كاملة على نسخة Debug وراقب Logcat (الوسم `ExternalLauncher`). إن ظهر نطاق دفع أو تسجيل دخول خرج إلى المتصفح أضفه إلى `TRUSTED_FLOW_HOST_SUFFIXES`، واحذف من القائمة البوابات التي لا يستخدمها المتجر. القائمة الحالية تخمينية (بوابات شائعة في المنطقة: Tap وMoyasar وTabby وTamara وHyperPay وPayTabs وCheckout.com وPayPal).
4. **نطاقات فرعية للمتجر:** إن كان المتجر يستخدم نطاقًا فرعيًا (مثل `checkout.` أو `accounts.`) أضفه إلى `STORE_HOSTS`.
5. **تسجيل الدخول بحساب Google:** تمنع Google تسجيل الدخول داخل WebView (`disallowed_useragent`). إن كان المتجر يوفّره فلن يعمل داخل التطبيق؛ يبقى الدخول برقم الجوال أو البريد. والحل الكامل يتطلب تسجيل دخول أصلي (Credential Manager) بالتنسيق مع منصة المتجر.
6. **Apple Pay** غير متاح على Android. **Google Pay** داخل WebView يعمل فقط إذا كانت البوابة تدعم Payment Request في WebView. اختبر وسائل الدفع واحدة واحدة.
7. **App Links:** ليفتح رابط المتجر التطبيق مباشرة، ارفع إلى الموقع الملف `https://wfcostore.com/.well-known/assetlinks.json`:
   ```json
   [{
     "relation": ["delegate_permission/common.handle_all_urls"],
     "target": {
       "namespace": "android_app",
       "package_name": "com.wfcostore.app",
       "sha256_cert_fingerprints": ["<SHA-256 من Play Console → App integrity>"]
     }
   }]
   ```
   إن لم تكن لديك صلاحية رفع ملفات على الدومين (حسب منصة المتجر)، فالروابط تُفتح في المتصفح، وهذا لا يؤثر على عمل التطبيق.
8. **السحب للتحديث:** إن كان الموقع يستخدم قوائم جانبية أو نوافذ تمرير داخلية وظهر التحديث أثناء تمريرها، عطّله: `ENABLE_PULL_TO_REFRESH = false`.

## 10. حالة الاختبارات

| الاختبار | الحالة |
|---|---|
| قواعد التنقل `UrlPolicyTest` (14 حالة: المتجر، HTTP، واتساب/هاتف/بريد، intent، إعادة التوجيه، بوابات الدفع، المخططات الخطرة، الروابط المشوّهة) | ✅ نجح (على JVM باستخدام ملفات المصدر نفسها) |
| التحقق من صحة ملفات XML | ✅ نجح |
| `assembleDebug` / `bundleRelease` | ⛔ لم يُنفَّذ: `dl.google.com` محجوب في بيئة البناء |
| `MainActivityTest` (التشغيل، إعادة الإنشاء) | ⛔ مكتوب ولم يُشغّل (لا محاكي) |
| التشغيل الأول، الصفحة الرئيسية، التنقل، زر الرجوع | ⛔ يتطلب جهازًا |
| فقدان الإنترنت واستعادته، الروابط الخارجية | ⛔ يتطلب جهازًا |
| تسجيل الدخول، السلة، تحديث الكميات، الحذف | ⛔ يتطلب جهازًا والوصول إلى الموقع |
| الدفع والعودة للمتجر، الشحن | ⛔ يتطلب جهازًا وحساب اختبار أو طلبًا حقيقيًا |
| أحجام الشاشات، الدوران، الوضع الليلي | ⛔ يتطلب جهازًا |

**قائمة اختبار يدوية مقترحة** (على جهاز حقيقي بنسخة Debug):
1. تثبيت جديد → شاشة البداية → الرئيسية تظهر خلال ثوانٍ، دون شاشة بيضاء دائمة.
2. فتح قسم ← منتج ← اختيار الخيارات ← إضافة إلى السلة ← تعديل الكمية ← حذف.
3. تسجيل الدخول ← إغلاق التطبيق من قائمة التطبيقات الأخيرة ← إعادة فتحه: يجب أن تبقى الجلسة والسلة.
4. إتمام الطلب حتى صفحة الدفع، ثم الإلغاء والعودة: يجب الرجوع إلى المتجر داخل التطبيق.
5. وضع الطيران أثناء التصفح ← شاشة «لا يوجد اتصال» ← إيقاف وضع الطيران ← إعادة تحميل تلقائية.
6. زر واتساب/الاتصال في الموقع ← يفتح التطبيق المناسب، والنقر المزدوج لا يفتحه مرتين.
7. تدوير الشاشة في صفحة منتج مع تمرير ← لا إعادة تحميل.
8. زر الرجوع من الرئيسية ← يغلق التطبيق.
9. رابط خارجي (مثلًا في الفوتر) ← يفتح في المتصفح.
10. الإعدادات ← الوضع الليلي، وحجم خط كبير، وشاشة صغيرة (5") وجهاز لوحي.

## 11. متطلبات النشر الخارجية

- **حساب Google Play Console:** رسوم تسجيل لمرة واحدة (25 دولارًا أمريكيًا وقت الكتابة؛ تحقّق من الرقم الحالي). الحسابات الشخصية الجديدة ملزمة باختبار مغلق (عدد من المختبرين لمدة محددة) قبل النشر للعامة؛ حساب «منظمة» يتطلب رقم D-U-N-S.
- **سياسة خصوصية** على رابط عام (يمكن استخدام صفحة سياسة الخصوصية في المتجر إن وُجدت).
- نموذج **Data safety** وتصنيف المحتوى ولقطات شاشة وأيقونة 512×512 وصورة مميزة 1024×500.
- **سياسة Google Play بشأن تطبيقات WebView:** التطبيقات التي تعرض موقعًا فقط قد تُرفض لقلة الوظائف («Minimum functionality»/«Webview spam»). يساعد في القبول أن التطبيق يخص صاحب الموقع نفسه، ويعمل جيدًا مع الرجوع والأخطاء وعدم الاتصال. يجب أن يكون الناشر صاحب المتجر أو مفوّضًا منه.
- لا توجد مفاتيح API أو خدمات مدفوعة مطلوبة لتشغيل التطبيق.

## 12. ما تُرك عمدًا للمستقبل

لم تُضف إشعارات Push أو Firebase أو تسجيل دخول أصلي أو قاعدة بيانات. البنية تسمح بإضافتها:
- **الإشعارات:** Firebase Cloud Messaging + `google-services.json` وصلاحية `POST_NOTIFICATIONS` (Android 13+). الإشعار يفتح رابط المتجر عبر `onNewIntent` الموجود.
- **التحليلات:** يمكن للموقع التمييز بين زيارات التطبيق والمتصفح عبر الإضافة `WFCostoreAndroid/<version>` في User-Agent.
- **جسر JavaScript:** غير موجود. إن احتجته يومًا فاقصره على `STORE_HOSTS` عبر `WebViewCompat.addWebMessageListener` مع قائمة أصول مسموحة، لا عبر `addJavascriptInterface`.
