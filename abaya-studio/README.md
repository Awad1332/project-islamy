# Abaya Studio AI — منصة تصميم العباية الذكية

استوديو تصميم عبايات رقمي لمتاجر العبايات في السوق السعودي.
العميلة: **تختار ← تصمم ← تشاهد ← تعدّل ← تعرف السعر والمقاس ← تشتري.**
التاجر: **يرفع الخيارات ← يحدد الأسعار والتوافق ← يحصل على طلبات + بيانات تفضيلات السوق.**

## التشغيل

```bash
cd abaya-studio
npm install
npm run dev          # http://localhost:3000
npm test             # اختبارات المحركات (Configuration / Pricing / Size / Prompt / Analytics)
npm run build && npm start
```

عند أول تشغيل يُنشأ متجر تجريبي (`demo`) مع نحو 2,000 تصميم تجريبي حتى تظهر لوحة التاجر ببيانات واقعية.
تُحفظ البيانات في `data/db.json`. احذفيه لإعادة البيانات التجريبية.

| الصفحة | المسار |
|---|---|
| تجربة العميلة (الاستوديو) | `/studio` |
| مساعد المقاس المستقل | `/size` |
| رابط مشاركة التصميم | `/d/AB10294` |
| السلة | `/cart` |
| لوحة التاجر | `/dashboard` (الدخول برمز OTP. في وضع التطوير يظهر الرمز على الشاشة، والبريد الافتراضي `owner@demo.sa`) |

## ما تم بناؤه (MVP)

**تجربة العميلة (Mobile First، RTL):**
- شاشة ترحيب فيها موديل تتغير عبايتها تلقائيًا، وزر «ابدئي التصميم».
- 8 خطوات، كل خطوة فيها قرار واحد: القصة، الطول (مع «أحتاج مساعدة في اختيار الطول»)، الأكمام، الرقبة، الإغلاق، الخامة، اللون، ثم اللمسات الأخيرة (التطريز والإضافات).
- كل خيار يظهر كبطاقة مرئية. الصور تُرسم تلقائيًا من التصميم نفسه، أو تُستخدم صورة التاجر إن وُجدت. الخامات والألوان تظهر كعينات قماش.
- معاينة حية ثابتة في أعلى الشاشة على الجوال وعلى اليمين في الديسكتوب، وفيها: أمام/خلف، تكبير وتصغير، سحب للتحريك، تركيز تلقائي على منطقة الخطوة الحالية، وإعادة التصميم من البداية.
- السعر يظهر طوال الوقت ويتحدث فورًا، مع تفاصيل السعر ومدة التنفيذ.
- نظام توافق حقيقي: الخيار غير المتوافق يظهر عليه «غير متوافق»، وعند الضغط عليه تظهر رسالة مثل «هذا التطريز غير متوفر مع هذه القصة (كلوش).» مع زر «شاهدي الخيارات المتوافقة». وإذا غيّرت العميلة خطوة سابقة، يعدّل المحرك الاختيارات اللاحقة غير المتوافقة تلقائيًا ويخبرها بما تغيّر.
- «✨ شاهدي عبايتك»، ثم حالة «جاري تصميم عبايتك...»، ثم صفحة النتيجة «هذه عبايتك ✨» وفيها: التفاصيل، السعر، المقاس المقترح مع «لماذا هذا المقاس؟»، و«صمميها مرة ثانية» (غيري اللون/الطول/الأكمام/التطريز/الخامة بدون الرجوع للبداية)، وأزرار: أضيفي للسلة، عدّلي، احفظي (`Abaya Design #AB10294`)، شاركي (رابط فيه «شوفي العباية اللي صممتها»).
- مساعد مقاس من 5 أسئلة، سؤال في كل شاشة. يعطي المقاس ودرجة الملاءمة والأسباب، ويعتمد على جدول المقاسات وقواعد التاجر فقط.
- حالات الواجهة كلها مصممة: التحميل، الفراغ، الخطأ مع إعادة المحاولة، النجاح، التعطيل، غير المتوفر، غير المتوافق، التوليد، الحفظ، والإضافة للسلة.

**لوحة التاجر:**
- **الرئيسية:** التصميمات، المضافة للسلة، المتحولة لطلب، ومتوسط قيمة التصميم، مع المقارنة بالفترة السابقة. وفيها رسم بياني يومي ومسار التحويل.
- **التفضيلات:** أكثر القصات والأطوال والألوان والخامات والأكمام والتطريز والإضافات (لآخر 7 أو 30 أو 90 يومًا).
- **Trend Lab («ماذا تريد العميلات؟»):** أكثر تركيبة تم اختيارها، و«فرصة جديدة» بصياغة احتمالية وليست جزمًا، والتركيبات الرائجة، والخيارات التي ترتفع أو تنخفض.
- **حوّل إلى منتج:** من أي تصميم أو من تركيبة في Trend Lab. ينشئ Product Template فيه الاسم، الصور، السعر، SKU، المقاسات، المكونات، ومدة التنفيذ.
- **خيارات التصميم:** لكل خيار: الاسم، الصورة، السعر، التوفر، SKU، مدة التنفيذ، الخيارات المتوافقة فقط، والخيارات غير المتوافقة. وفيها أيضًا إعدادات السعر الأساسي.
- **المقاسات:** جدول مقاسات وقواعد حساب قابلة للتعديل، مع تجربة فورية للنتيجة.

## البنية التقنية

```
Store → Configurator (UI) → Configuration Engine → Pricing Engine
      → AI Prompt Builder → AI Visualization → Cart
```

- **Frontend:** Next.js 15 (App Router) + React 19 + Tailwind CSS 4
- **Backend:** Next.js Route Handlers (Node.js). كل شيء خلف واجهة `Repository`.
- **Database:** محوّل JSON مدمج يعمل بدون إعداد. والمخطط الكامل لـ PostgreSQL في `db/schema.sql`.
- **Auth:** Email OTP (رمز مُجزّأ hash، ينتهي خلال 10 دقائق، 5 محاولات كحد أقصى، rate limit) مع جلسة موقّعة HMAC، ومحمية بـ middleware.
- **Storage:** واجهة `putFile/getFile` على القرص المحلي، جاهزة للاستبدال بـ S3 أو R2.
- **AI:** واجهة `ImageProvider`. المزود الافتراضي يرسم تصورًا توضيحيًا فوريًا. وعند ضبط `OPENAI_API_KEY` يُستخدم OpenAI Images، وإذا فشل يرجع تلقائيًا للرسم التوضيحي.

### أهم قاعدة: الذكاء الاصطناعي لا يحدد المواصفات

```
src/lib/engine/
  config.ts     ← Configuration Engine: التوفر، التوافق (blacklist + whitelist، بالاتجاهين)،
                  normalize، select، validate، SKU
  pricing.ts    ← Base + add-ons + مدة التنفيذ
  prompt.ts     ← يحوّل الإعداد المعتمد إلى spec + prompt (+ negative prompt)
  size.ts       ← توصية المقاس من جدول التاجر وقواعده (بدون AI)
  analytics.ts  ← KPIs، التوزيعات، التركيبات، المتغيرات (دوال نقية قابلة للنقل إلى SQL)
src/lib/render/ ← رسم SVG للعباية حسب الإعداد (المعاينة، صور البطاقات، والتصور الاحتياطي)
```

الخادم يعيد التحقق من كل تصميم ويعيد تسعيره قبل الحفظ أو التوليد أو الإضافة للسلة. السعر المرسل من المتصفح لا يُعتمد أبدًا، والتصميم غير المتوافق يُرفض برمز 422.

### واجهات API

| Endpoint | الوظيفة |
|---|---|
| `GET /api/catalog?store=` | خيارات المتجر |
| `POST /api/configure` | تطبيق اختيار والتحقق من الإعداد وتسعيره (للتكاملات مثل سلة وشوبيفاي) |
| `POST /api/designs` · `GET/PATCH /api/designs/:code` | حفظ التصميم وتعديله |
| `POST /api/visualize` | توليد التصور (أمام وخلف) |
| `GET /api/render?design=CODE&view=back` | صورة SVG للتصميم |
| `POST /api/size` | توصية المقاس |
| `GET/POST/DELETE /api/cart` · `POST /api/cart/checkout` | السلة وإتمام الطلب |
| `/api/merchant/*` | الخيارات، الإعدادات، والمنتجات (تتطلب جلسة تاجر) |

إعدادات البيئة موضحة في `.env.example`.
