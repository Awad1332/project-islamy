# 11 — الربط مع سلة في الأدلة، تحليل السوشيال، مساعد نبض، واللهجة

## 1. ربط الأدلة مع سلة

كل دليل في نبض مربوط بسلة بثلاث طرق:

| الطريقة | وش تسوي | الباقة | كيف تُبنى |
|---------|---------|--------|-----------|
| **افتح لوحة سلة** | زر يفتح لوحة تحكم التاجر في سلة، ومعه المسار المكتوب (مثل: التسويق ← كوبونات التخفيض) | كل الباقات | رابط للوحة سلة. إذا وفّرت سلة روابط مباشرة لكل صفحة نستخدمها. يجب التحقق من شكل الروابط |
| **نبض يتأكد من سلة** | بعد ما يخلص التاجر، يضغط «خلصت؟ خلّ نبض يتأكد» ونبض يشيك عبر Salla API إن الشي انسوى فعلًا، ويعطيه النقاط | كل الباقات (للمهام اللي يمكن فحصها) | قراءة من API: الكوبونات، المنتجات (العدد والصور والوصف)، الصفحات، طرق الدفع والشحن إن كانت متاحة. أو Webhooks مثل إضافة منتج |
| **سوّها لي بدالي** | نبض ينفّذ المهمة في سلة مباشرة | النمو والاحترافية | كتابة عبر API: إنشاء كوبون، وعرض خاص لاحقًا. **بموافقة التاجر قبل كل تنفيذ** |

**مركز مساعدة سلة**: كل دليل فيه زر لمركز المساعدة الرسمي، للي يبي شرح إضافي من سلة نفسها.

**ما نقدر نسويه**: نبض ما يقدر يعدّل أو يضيف أزرار داخل لوحة سلة نفسها، فالدليل يكون في نبض جنبها.

### جدول الفحص التلقائي (للنسخة الحقيقية)
| المهمة | وش نفحص | المصدر |
|--------|---------|--------|
| الكوبون | كوبون فعّال أُنشئ بعد بداية المهمة | Coupons API |
| أول 10 منتجات | عدد المنتجات المنشورة، وعدد الصور، وطول الوصف | Products API + Webhook |
| صفحات الثقة | وجود صفحات الاستبدال والشحن ومن نحن | ⚠️ يُتحقق من توفرها في API |
| طرق الدفع والشحن | الطرق المفعّلة | ⚠️ يُتحقق من توفرها في API |
| السلات المتروكة | إعدادات التذكير، أو وصول رسائل تذكير | ⚠️ يُتحقق. البديل: سؤال التاجر |
| حد الشحن المجاني | إعداد الشحن المجاني | ⚠️ يُتحقق |

**إذا ما كان الفحص متاحًا**: المهمة تبقى «سوّيتها ✓» يضغطها التاجر بنفسه، وما نوهمه إننا تأكدنا.

## 2. تحليل السوشيال ميديا المعمّق

### الأقسام
1. **صحة الحساب (من 100)**: الانتظام (منشورات الأسبوع مقابل الهدف)، والتفاعل، واكتمال البروفايل، وتحويل الزيارات لطلبات.
2. **متى متابعينك متواجدين؟** جدول لأيام الأسبوع مع 4 فترات (الصبح، الظهر، العصر، الليل) من بيانات تفاعل الحساب.
3. **وش نوع المحتوى اللي يمشي؟** مقارنة بين الريلز والصور والستوري.
4. **أفضل وأضعف منشور** هذا الأسبوع، مع الزيارات والطلبات اللي جابها.
5. **البروفايل**: قائمة فحص، وبايو مقترح.
6. **من السوشيال للمتجر**: الزيارات والطلبات ونسبة الشراء، عن طريق متتبع نبض وروابط UTM والكوبونات.
7. **خطة تنشيط هذا الأسبوع**: 5 خطوات عملية.

### التوجيه لقسم ثاني
إذا النصيحة معلوماتها أو تنفيذها في قسم ثاني، يطلع جنبها زر يوديه له:

| النصيحة | يوديه لـ |
|---------|----------|
| انشر ريلز أكثر | صانع المحتوى |
| جهّز حملة يوم الراتب | الخطة التسويقية |
| حط كود خاص للمتابعين | مهمة الكوبون في رحلتي |
| الزيارات ما تتحول لطلبات | رحلتي (تحسين صفحات المنتجات)، أو نبض الذكي من 100 طلب |
| منتج خلص أو تغيّر | مراقبة المتجر |

**قاعدة عامة في كل المنتج**: ما نكرر المعلومة في أكثر من مكان. القسم يعطي الخلاصة، ويودّي للقسم المسؤول عن التفاصيل.

### حسب الباقة
- **المجانية والأساسية**: صحة الحساب + أهم نصيحتين (تحليل مختصر)، والباقي مقفل ويظهر ضبابي.
- **النمو والاحترافية**: التحليل كامل + خطة التنشيط الأسبوعية.

### حدود البيانات
- **إنستقرام**: الأوقات والتفاعل من Instagram Graph API (حساب أعمال أو صانع محتوى).
- **تيك توك**: عبر واجهات تيك توك للأعمال بعد موافقة التطبيق.
- **الطلبات من السوشيال**: تحتاج روابط بتتبع أو كوبونات لكل منصة، وإلا نعرض الزيارات بس.

## 3. مساعد نبض (اسأل نبض)

### الفكرة
زر ثابت «اسأل نبض» في كل الصفحات. التاجر يكتب سؤاله بلهجته، أو يختار سؤالًا جاهزًا.

### القاعدة الأساسية: الإجابة حسب الباقة
| الحالة | الإجابة |
|--------|---------|
| السؤال داخل باقته | إجابة كاملة من **أرقام متجره**، مع زر للقسم المرتبط، ومكتوب تحتها «من بيانات متجرك في سلة ونبض» |
| السؤال يحتاج باقة أعلى | **إجابة مختصرة عامة** (مفيدة، مو فاضية)، وبعدها: «هذي إجابة مختصرة. إذا تبي إجابة بمسار أوضح (...)، اشترك في باقة كذا (السعر) وتفتح لك هالميزة» مع زر للباقات، ومكتوب تحتها «إجابة عامة، مو من أرقام متجرك» |
| ما فهم السؤال | يقول بصراحة إنه ما فهم، ويقترح مواضيع يقدر يساعد فيها |

### أمثلة
| السؤال | الباقة المطلوبة للإجابة الكاملة |
|--------|------------------|
| وش مهمتي الحين؟ | كل الباقات |
| كيف أسوي كوبون؟ | الأساسية (الدليل المصوّر) |
| وش أنشر اليوم؟ | الأساسية (تقويم المحتوى) |
| الشحن المجاني كم أحطه؟ | الأساسية |
| ليش مبيعاتي نزلت؟ | النمو (تحليل بأرقام المتجر) |
| كيف أنشّط حسابي؟ | النمو (تحليل السوشيال) |
| أبي خطة تسويقية | النمو |
| أبي أكلم خبير | الاحترافية |

### قواعد الذكاء الاصطناعي في المساعد (نفس قواعد نبض)
1. **ما يخترع أرقام.** كل رقم من أدوات محددة تقرأ بيانات المتجر (مثل: `get_kpis`، `get_social_insights`، `get_next_task`، `get_opportunities`، `get_guide`).
2. **يفرّق بين المؤكد والمحتمل**: «هذا مؤكد من السجل» أو «غالبًا».
3. **ما يوعد بنتائج**: «تقريبًا، مو وعد».
4. **يعرف باقة التاجر**: الأداة ترجع له الأشياء المسموحة، والنموذج نفسه ما يقرر الصلاحية.
5. **ما يشارك بيانات شخصية** لعملاء التاجر.
6. **حد استخدام شهري** حسب الباقة، للتحكم في التكلفة.

### التقنية
- نموذج Claude مع أدوات (Tool use) مغلقة، بدون استعلامات حرة على قاعدة البيانات.
- كل إجابة تمر على نفس المدقق اللي يرفض أي رقم مو موجود في البيانات (الوثيقة 05).
- تسجيل الأسئلة اللي ما فهمها المساعد، عشان نضيف لها إجابات ومحتوى.
- **الأسئلة اللي تحتاج ترقية** تُسجَّل، وتُعرض في لوحة الإدارة كفرص بيع (بدون نص السؤال الكامل إذا فيه بيانات حساسة).

## 4. اللهجة السعودية في الأداة

كل نصوص الأداة (العناوين، والأزرار، والشروحات، والمساعد) باللهجة السعودية البيضاء، المفهومة في كل المناطق.

| بدل | نكتب |
|-----|------|
| مرحبًا | هلا والله |
| ماذا أفعل؟ | وش أسوي؟ |
| لماذا | ليش |
| الآن | الحين |
| تريد | تبي |
| أغلق | سكّر |
| تم | خلصت / تم |
| لاحقًا | بعدين |
| ترقية | رقّ باقتك |
| أحسنت | كفو / يعطيك العافية |
| مجانًا | ببلاش |
| حتى / إلى | لين |
| التالي / السابق | اللي بعده / اللي قبل |

**قواعد الكتابة**:
- جمل قصيرة، وكلمة إنجليزية بس لو هي المستخدمة فعلًا (ريلز، ستوري، بايو).
- محترمة وقريبة، مثل أخ خبير يكلمك. بدون مبالغة ولا «ترند».
- **الأرقام والتقديرات** تبقى دقيقة وواضحة، مع «تقريبًا» أو «تقدير».
- **الشروط والخصوصية والفواتير** بالفصحى البسيطة، لأنها وثائق رسمية.
- كاتب محتوى يراجع كل النصوص قبل الإطلاق، ويتأكد إن اللهجة مفهومة لتاجر من الرياض وجدة والدمام وأبها.
